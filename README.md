# DailyEmailNotification

### Локальный ИИ-ассистент для автоматизации электронной почты

Приложение на **C# / .NET 8**, которое получает письма Gmail,
обрабатывает их с помощью локальной модели **Qwen 3.5 4B** и отправляет
ответы.

------------------------------------------------------------------------

## О проекте

**DailyEmailNotification** --- фоновое приложение для автоматизации
обработки электронной почты. Оно интегрируется с Gmail через IMAP/SMTP,
использует локальную языковую модель через Ollama и сохраняет историю
переписки в Microsoft SQL Server.

Приложение развёрнуто на Windows-компьютере и работает как **Windows
Service**. Планирование фоновых операций выполняется с помощью
Quartz.NET.

## Возможности

-   Получение входящих писем через Gmail IMAP.
-   Фильтрация входящих сообщений по списку разрешённых отправителей.
-   Извлечение текстового содержимого писем, в том числе из HTML.
-   Генерация ответов с помощью локальной модели Ollama.
-   Передача контекста переписки модели для формирования
    последовательных ответов.
-   Отправка писем через Gmail SMTP.
-   Хранение пользователей, диалогов, сообщений и их статусов в SQL
    Server.
-   Фоновая обработка входящей почты и очереди исходящих сообщений.
-   Ежедневная автоматическая email-рассылка.
-   Запуск приложения в качестве Windows Service.

> **Примечание:** наличие у модели Ollama поддержки Vision не означает,
> что обработка изображений и вложений уже реализована в приложении. Для
> этого требуется отдельная интеграция.

### Основные сценарии работы

**Обработка входящего письма:**

1.  `IncomingEmailJob` запускает проверку входящей почты.
2.  `IncomingEmailReader` получает письма через IMAP и применяет фильтр
    отправителей.
3.  `ProcessEmailRequestService` организует обработку сообщения и
    получение контекста переписки.
4.  `OllamaAIService` отправляет запрос локальной модели.
5.  Результат сохраняется в базе данных и подготавливается к отправке.

**Отправка ответа:**

1.  `OutboxEmailJob` проверяет очередь исходящих сообщений.
2.  `OutboxEmailService` обрабатывает ожидающие отправки сообщения.
3.  Письмо отправляется через Gmail SMTP.
4.  Статус сообщения обновляется в SQL Server.

## Хранение данных

Приложение использует Microsoft SQL Server и Entity Framework Core.

Основные таблицы AI-ассистента:

-   `AppUsers` --- пользователи приложения.
-   `Conversations` --- диалоги.
-   `Messages` --- входящие и исходящие сообщения, их статусы и ошибки.
-   `UserContexts` --- дополнительный контекст пользователя.

Для ежедневной рассылки также используются таблицы `EmailRecipients` и
`EmailNotifications`.

## Планирование задач

Фоновые задачи регистрируются в Quartz.NET.

Последняя известная конфигурация расписания:

  Задача               Расписание
  -------------------- ------------------------------------------
  `IncomingEmailJob`   Каждую минуту
  `OutboxEmailJob`     Каждые 30 секунд
  `DailyEmailJob`      Ежедневно в 21:50 по московскому времени

Cron-выражение ежедневной задачи:

``` csharp
.WithCronSchedule(
    "0 50 21 * * ?",
    x => x.InTimeZone(moscowTimeZone))
```

Проверьте актуальное расписание в `Program.cs`: оно может отличаться от
указанного здесь после изменения конфигурации.

## Развёртывание

Приложение рассчитано на локальный запуск в Windows.

Текущая конфигурация компьютера, на котором развёрнут проект:

  -----------------------------------------------------------------------------------------------------------
  Компонент                           Конфигурация
  ----------------------------------- -----------------------------------------------------------------------
  Windows Service                     `DailyEmailNotification`

  Исполняемый файл                    `E:\DailyEmailNotification\publish\DailyEmailNotification.Worker.exe`

  Каталог публикации                  `E:\DailyEmailNotification\publish\`

  SQL Server                          `localhost\MSSQLSERVER01`

  База данных                         `DailyEmailNotificationDb`

  Ollama API                          `http://localhost:11434`

  Модель                              `qwen3.5:4b`

  Gmail IMAP                          `imap.gmail.com:993`

  Gmail SMTP                          `smtp.gmail.com:587`
  -----------------------------------------------------------------------------------------------------------

Ollama установлена локально и запускается через Планировщик заданий
Windows. Для работы приложения должны быть доступны SQL Server, Ollama,
Gmail и интернет-соединение.

**Это локальный хостинг, а не облачный сервер.** Если компьютер
выключен, находится в спящем режиме или потерял доступ к сети, обработка
почты приостанавливается.

## Конфигурация

Настройки приложения задаются через `appsettings.json` и переменные
окружения.

Пример строки подключения к SQL Server:

``` text
Server=localhost\MSSQLSERVER01;Database=DailyEmailNotificationDb;Trusted_Connection=True;TrustServerCertificate=True;
```

Параметры Ollama:

``` json
{
  "Ollama": {
    "BaseUrl": "http://localhost:11434",
    "Model": "qwen3.5:4b"
  }
}
```

Фактические имена секций должны соответствовать конфигурационным классам
проекта.

### Секреты

Не храните пароли и токены в Git-репозитории.

Для SMTP используется переменная окружения `Smtp__Password`. Её можно
задать в PowerShell от имени администратора:

``` powershell
[Environment]::SetEnvironmentVariable(
    "Smtp__Password",
    "YOUR_GOOGLE_APP_PASSWORD",
    "Machine"
)
```

После изменения машинных переменных окружения перезапустите Windows
Service.

Для локальной разработки используйте .NET User Secrets или переменные
окружения. Убедитесь, что секреты и локальные конфигурационные файлы
исключены из Git через `.gitignore`.


### Публикация

``` powershell
dotnet publish `
  "E:\DailyEmailNotification\DailyEmailNotification\DailyEmailNotification.Worker.csproj" `

  -o "E:\DailyEmailNotification\publish"
```

### Обновление существующей Windows Service

Откройте PowerShell от имени администратора.

Остановите службу:

``` powershell
Stop-Service -Name "DailyEmailNotification"
```

Опубликуйте новую версию командой выше, затем запустите службу:

``` powershell
Start-Service -Name "DailyEmailNotification"
```

Проверьте состояние:

``` powershell
Get-Service -Name "DailyEmailNotification"
```

Посмотреть конфигурацию зарегистрированной службы:

``` powershell
sc.exe qc DailyEmailNotification
```

Служба уже зарегистрирована в Windows. Не выполняйте `sc.exe create`,
если она существует.

## Текущие ограничения

-   Обработка изображений и файловых вложений требует отдельной
    реализации в почтовом конвейере и передаче данных в Ollama.
-   Просьба пользователя «отправить через 5 минут» не становится
    отложенной задачей автоматически. Для этого нужен отдельный механизм
    планирования отправки.
-   Повторная обработка сообщений со статусом `Failed` требует
    отдельного сценария повторной постановки в обработку.
-   При повторной отправке после неопределённого результата SMTP
    необходимо учитывать риск дублирования писем.
